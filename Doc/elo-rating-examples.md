# ELO Rating – Παραδείγματα βήμα‑βήμα

Σε αυτό το έγγραφο παίρνουμε τη θεωρία από τα άλλα δύο docs και την εφαρμόζουμε σε **συγκεκριμένα παραδείγματα** με αριθμούς.

> Πώς να το διαβάσεις:
> - Δες το σαν **λυμένα παραδείγματα** – κάθε βήμα είναι μια απλή αριθμητική πράξη.
> - Δεν χρειάζεται να θυμάσαι τύπους απ’ έξω· απλώς ακολούθησε τη ροή: βάζουμε τα νούμερα, υπολογίζουμε, εξηγούμε τι σημαίνει.
> - Αν θες να υλοποιήσεις κώδικα, αυτά τα παραδείγματα μπορούν να μετατραπούν σχεδόν 1‑1 σε helpers.

Θα δούμε:

1. Πώς λειτουργεί το **απλό ELO** (μόνο win/draw/loss).
2. Πώς αλλάζει το αποτέλεσμα όταν βάλουμε μέσα **AVG και High Run**.

Για αναφορά:

- `elo-rating-overview.md` → βασική θεωρία ELO.
- `elo-rating-billiards.md` → πώς προσθέτουμε AVG & H.R. στο μπιλιάρδο.

---

## 1. Παράδειγμα – Βασικό ELO χωρίς performance

### 1.1. Δεδομένα

Έστω ότι έχουμε:

- Παίκτης A: `R_A = 1800`.
- Παίκτης B: `R_B = 1900`.
- Αποτέλεσμα match: **A κερδίζει**.
- K‑factor: `K = 20`.

### 1.2. Τι περιμέναμε πριν τον αγώνα (Expected score)

Θυμίζουμε τον τύπο για τον A σε πιο "χειροπιαστή" μορφή:

```text
E_A = 1 / (1 + 10 ^ ((R_B - R_A) / 400))
```

Βάζουμε τα νούμερα:

```text
E_A = 1 / (1 + 10 ^ ((1900 - 1800) / 400))
    = 1 / (1 + 10 ^ (100 / 400))
    = 1 / (1 + 10 ^ 0.25)
```

Υπολογιστικά:

- `10^0.25 ≈ 1.78`

Άρα:

```text
E_A ≈ 1 / (1 + 1.78) ≈ 0.36
```

Ερμηνεία:

- Ο A, με χαμηλότερο rating, είναι **αουτσάιντερ**.
- Περιμένουμε να πάρει ~36% του score.

Για τον B:

```text
E_B = 1 - E_A ≈ 1 - 0.36 = 0.64
```

Ο B είναι το φαβορί με ~64%.

### 1.3. Τι έγινε στον αγώνα (Actual score)

Ο A κερδίζει:

- `S_A = 1.0`
- `S_B = 0.0`

### 1.4. Νέο rating με τη βασική φόρμουλα

**Βήμα 1 – Γράφουμε τη φόρμουλα**

Η βασική φόρμουλα του ELO για τον A είναι:

```text
R'_A = R_A + K * (S_A - E_A)
```

Δηλαδή: νέο rating = παλιό rating + K × (τι έκανε − τι περιμέναμε).

**Βήμα 2 – Βάζουμε τα νούμερα του παραδείγματος**

Ξέρουμε ότι:

- `R_A = 1800`
- `K = 20`
- `S_A = 1.0` (γιατί κέρδισε)
- `E_A ≈ 0.36`

Οπότε:

```text
R'_A = 1800 + 20 * (1.0 - 0.36)
     = 1800 + 20 * 0.64
     = 1800 + 12.8
     ≈ 1813
```

Άρα ο A κερδίζει περίπου **+13 rating points** (από 1800 πάει ~1813).

**Βήμα 3 – Το ίδιο για τον B**

Για τον B χρησιμοποιούμε την ίδια λογική:

- `R_B = 1900`
- `S_B = 0.0` (έχασε)
- `E_B ≈ 0.64`

```text
R'_B = R_B + K * (S_B - E_B)
     = 1900 + 20 * (0 - 0.64)
     = 1900 - 12.8
     ≈ 1887
```

Ο B χάνει περίπου **13 βαθμούς** (από 1900 πάει ~1887).

**Λογική**:

- Ο A έκανε "έκπληξη" απέναντι σε πιο δυνατό παίκτη → κερδίζει αρκετούς πόντους.
- Ο B έχασε ενώ ήταν φαβορί → τιμωρείται αντίστοιχα.

## 2. Παράδειγμα – ELO με AVG & High Run (μόνο για Player A)

Τώρα παίρνουμε **το ίδιο match** αλλά προσθέτουμε τα billiards‑stats για τον A.

### 2.1. Δεδομένα

Βασικά ratings και αποτέλεσμα όπως πριν:

- `R_A = 1800`, `R_B = 1900`, `K = 20`, A κερδίζει.

Στατιστικά match για τον A (Three‑Cushion):

- Στόχος: 40 πόντοι.
- Ο A κάνει 40 πόντους σε 20 innings → `AVG_A = 40/20 = 2.000`.
- Θεωρούμε αναμενόμενο AVG για αυτό το επίπεδο `AVG_expected = 1.500`.
- High Run: `H.R._A = 12`.
- Threshold για HR: `HR_threshold = 10`.
- Βάρος HR: `HR_weight = 0.02` (δηλαδή κάθε extra πόντος πάνω από το threshold προσθέτει 0.02 στο bonus factor).

Το `E_A` παραμένει ~0.36 όπως στο πρώτο παράδειγμα.

### 2.2. Base score

Επειδή ο A κερδίζει:

- `baseScore = 1.0`

### 2.3. Πόσο καλό ήταν το AVG (avgRatio)

Υπολογίζουμε το Ratio γράφοντάς το σαν απλή διαίρεση:

```text
avgRatio = AVG_A / AVG_expected = 2.000 / 1.500 ≈ 1.333
```

Κάνουμε clamp για να το περιορίσουμε [0.8, 1.2]:

```text
avgRatioClamped = 1.2
```

### 2.4. Bonus από High Run

Εφόσον `H.R._A = 12` και `HR_threshold = 10`:

```text
hrBonusFactor = HR_weight * (H.R._A - HR_threshold)
              = 0.02 * (12 - 10)
              = 0.02 * 2
              = 0.04
```

Και αν θέλουμε το περιορίζουμε σε max 0.5 (εδώ είμαστε πολύ κάτω).

### 2.5. Νέο effective K για τον A

Αν υποθέσουμε ότι ορίζουμε ένα νέο K ως εξής:

```text
K_eff = K * (0.8 + 0.4 * avgRatioClamped + hrBonusFactor)
```

Τότε, βάζοντας τα νούμερα του παραδείγματος:

```text
K_eff = 20 * (0.8 + 0.4 * 1.2 + 0.04)
      = 20 * (0.8 + 0.48 + 0.04)
      = 20 * 1.32
      = 26.4
```

Βλέπουμε ότι ο A, επειδή έπαιξε **πολύ καλύτερα από το αναμενόμενο AVG** και είχε και καλό H.R.,
παίρνει effective K μεγαλύτερο από το βασικό 20.

### 2.6. Νέο rating με το performance‑based K

Τώρα εφαρμόζουμε πάλι τη βασική φόρμουλα, αλλά με το νέο `K_eff`:

```text
R''_A = R_A + K_eff * (S_A - E_A)
      = 1800 + 26.4 * (1.0 - 0.36)
      = 1800 + 26.4 * 0.64
      = 1800 + 16.896
      ≈ 1817
```

Τώρα ο A κερδίζει περίπου **+17 rating points** αντί για +13.

Για τον B, αν χρησιμοποιήσουμε το ίδιο `K_eff` από την πλευρά του A (απλοποίηση για το παράδειγμα):

```text
R''_B = 1900 + 26.4 * (0 - 0.64)
      ≈ 1900 - 16.9
      ≈ 1883
```

**Σύγκριση**:

- Basic ELO: A πάει 1800 → ~1813 (+12.8).
- Με AVG & H.R.: A πάει 1800 → ~1817 (+16.9).

Ο A "αμείβεται" παραπάνω γιατί:

- Κέρδισε πιο δυνατό αντίπαλο.
- Έπαιξε με **πολύ καλό AVG**.
- Είχε **High Run πάνω από το threshold**.

## 3. Παράδειγμα – Ήττα με πολύ καλή απόδοση (Option A, PI ως S)

Σε αυτό το παράδειγμα θα δούμε πώς μπορεί μια **ήττα** με πολύ καλή εμφάνιση να "πονέσει" λιγότερο το rating, όταν χρησιμοποιούμε το `PI_final` στη θέση του `S_A` (Option A).

### 3.1. Δεδομένα

Κρατάμε τα ίδια ratings και K με πριν, αλλά τώρα ο A **χάνει**:

- `R_A = 1800`, `R_B = 1900`, `K = 20`.
- Αποτέλεσμα: ο A **χάνει** → `S_A = 0`, `S_B = 1`.
- `E_A ≈ 0.36` όπως στο Παράδειγμα 1.

Στατιστικά match για τον A:

- `AVG_A = 2.000` (πολύ καλό για το επίπεδο).
- `AVG_expected = 1.500`.
- `H.R._A = 22` (πολύ μεγάλο run).
- `HR_threshold = 10`, `HR_weight = 0.02`.

### 3.2. Τι θα γινόταν με απλό ELO

Με το basic ELO χρησιμοποιούμε `S_A = 0`:

```text
Δ_basic = K * (S_A - E_A)
        = 20 * (0 - 0.36)
        = 20 * (-0.36)
        = -7.2

R'_A_basic = 1800 + (-7.2) = 1792.8
```

Δηλαδή ο A θα έχανε περίπου **7 rating points**.

### 3.3. Υπολογισμός PI για αυτή την ήττα

**Βήμα 1 – Base score**

Επειδή ο A χάνει:

- `baseScore = 0.0`

**Βήμα 2 – AVG ratio**

```text
avgRatio = AVG_A / AVG_expected = 2.000 / 1.500 ≈ 1.333
```

Κάνουμε clamp [0.8, 1.2]:

```text
avgRatioClamped = 1.2
```

**Βήμα 3 – High Run bonus**

Ο A έχει `H.R._A = 22`, πάνω από το threshold 10:

```text
hrBonus = HR_weight * (H.R._A - HR_threshold)
        = 0.02 * (22 - 10)
        = 0.02 * 12
        = 0.24
```

**Βήμα 4 – Performance Index PI**

```text
PI = baseScore * avgRatioClamped + hrBonus
   = 0.0 * 1.2 + 0.24
   = 0.24
```

Εδώ δεν χρειάζεται clamp, γιατί το 0.24 είναι ήδη ανάμεσα σε 0 και 1, άρα `PI_final = 0.24`.

### 3.4. ELO update με PI ως S

Τώρα, αντί για `S_A = 0`, χρησιμοποιούμε `S_A = PI_final = 0.24` στη φόρμουλα:

```text
Δ_perf = K * (PI_final - E_A)
       = 20 * (0.24 - 0.36)
       = 20 * (-0.12)
       = -2.4

R'_A_perf = 1800 + (-2.4) = 1797.6
```

### 3.5. Σύγκριση basic vs performance

- **Basic ELO** (χωρίς AVG/HR):
  - A: 1800 → 1792.8 (**−7.2**)  
  - Μεγάλη πτώση, απλά επειδή έχασε.

- **ELO με PI ως S** (Option A):
  - A: 1800 → 1797.6 (**−2.4**)  
  - Πολύ μικρότερη πτώση, γιατί έπαιξε **πολύ καλά** σε AVG και H.R.

Έτσι βλέπουμε καθαρά την ιδέα:

- Μια **ήττα με σούπερ απόδοση** δεν τιμωρείται όσο μια κακή ήττα.
- Το σύστημα "βλέπει" ότι ο A είχε performance πολύ καλύτερο από το απλό `S_A = 0` και μειώνει τη ζημιά στο rating.

## 4. Παράδειγμα – Και οι δύο παίκτες με performance (ιδέα)

Στα παραπάνω κοιτάξαμε μόνο τον A. Σε ένα πλήρες σύστημα μπορούμε να κάνουμε:

- Υπολογισμό performance (AVG, H.R.) για **κάθε παίκτη ξεχωριστά**.
- `K_eff_A` με βάση τα stats του A.
- `K_eff_B` με βάση τα stats του B.

Και να ενημερώσουμε:

```text
R'_A = R_A + K_eff,A * (S_A - E_A)
R'_B = R_B + K_eff,B * (S_B - E_B)
```

Έτσι:

- Τα **μεγάλα runs του A** επηρεάζουν το δικό του rating.
- Τα **μεγάλα runs του B** επηρεάζουν το δικό του.

Αυτό είναι πιο δίκαιο, αλλά και πιο πολύπλοκο, και θέλει προσεκτικό tuning στα weights.

---

## 5. Τι να κρατήσεις από όλα αυτά

- Το ELO ξεκινά από **very simple βάση**: rating, expected score, actual score.
- Στο μπιλιάρδο μπορούμε να το κάνουμε πιο "έξυπνο" με:
  - AVG
  - High Run
  - βάρος τουρνουά
- Τα παραπάνω παραδείγματα δείχνουν πόσο αλλάζει το αποτέλεσμα όταν βάλουμε αυτά τα στοιχεία.

Αυτά τα νούμερα μπορούν μετά να μπουν σε helpers (π.χ. TypeScript functions) που να τρέχουν στον backend του BilliardToday μετά από κάθε match.
