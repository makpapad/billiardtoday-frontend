# UMB Events Ranking (UER) — αυτόματη ενημέρωση με το τέλος τουρνουά: **ΣΧΕΔΙΟ**

Ημ/νία: 08/10/2026 · Κατάσταση: **σχέδιο, δεν γράφτηκε κώδικας** (περιμένει την απόφαση του χρήστη
και το ΟΚ για Φάση Β). Για τη χειροκίνητη ροή που ισχύει σήμερα → `docs/ai/` + skill
`billiardtoday-tournaments` → `references/umb-events-ranking-uer.md`.

## 1. Ζητούμενο (όπως το έθεσε ο χρήστης)

«Όταν τελειώνει ένα τουρνουά που λαμβάνει μέρος στη βαθμολογία, μόλις δημοσιευτεί η τελική
κατάταξη να ενημερώνεται αυτόματα η βάση.»

## 2. Το σημείο σύνδεσης (hook) — βρέθηκε, δεν χρειάζεται νέος μηχανισμός

Η τελική κατάταξη ενός event γράφεται από **ένα** σημείο:

| Τι | Πού |
|---|---|
| Endpoint | `POST /bt-events/:id/publish-final-results` (`src/api/bt-event/routes/bt-event.ts`) |
| Handler | `bt-event.publishFinalResults` |
| Service | `src/services/finalResultsPublisher.ts` → `publishFinalResults` |
| Γιατί εκεί | Γράφει τα `bt_results_final` με `strapi.db.query().create()` — **lifecycle-free** (σκόπιμα, βλ. `references/final-results-publish-and-stats-recalc.md`), άρα ο αυτοματισμός **δεν** μπορεί να στηριχθεί στα lifecycles του `bt-result-final` |

## 3. Ροή (όλα με υπάρχοντα κομμάτια)

| # | Τι γίνεται | Τι το στηρίζει |
|---|---|---|
| 1 | Στο τέλος του `publishFinalResults`: αν το event είναι **στήλη της βαθμολογίας** και η κατάταξη βγήκε πλήρης → μπαίνει σε ουρά **μία** δουλειά με debounce (~60″, γιατί η δημοσίευση γράφει πολλές γραμμές μαζί) | Οι στήλες A–K είναι δηλωμένες ως `btEventId` στη μηχανή (`DEFAULT_UMB_EVENTS`, `src/services/cebRankingEngine.ts`) — δεν μαντεύουμε |
| 2 | Υπολογισμός κατηγορίας `umb-events` → artifact | `POST /api/ceb-ranking-publish/recompute` με `slug: umb-events` (υπάρχει) |
| 3 | Έλεγχος πηγής έναντι της επίσημης λίστας | `scripts/compare-umb-events-ranking.js` (υπάρχει) |
| 4α | 0 αποκλίσεις → **δημοσίευση** JSON frontend· η σελίδα δείχνει την αλλαγή **εντός ~5′** (`revalidate = 300`, χωρίς rebuild) | `POST /api/ceb-ranking-publish/publish` (υπάρχει) |
| 4β | Αποκλίσεις > 0 → **δεν δημοσιεύει**, ειδοποίηση με τη διαφορά | ntfy (ήδη στημένο για το UMB audit) + toast στο PC |

Η ίδια ροή καλύπτει και **διόρθωση** τελικής κατάταξης αργότερα (κάθε επαναδημοσίευση
ξαναϋπολογίζει).

**Οι 11 στήλες της τρέχουσας έκδοσης (btEventId):** A=525 (WC Blois 26), B=332, C=331, D=330,
E=328, F=327, G=326, H=481, I=493, J=499, K=514.

## 4. Τι λείπει για να είναι πραγματικά αυτόματο

1. **Φάση Β στην παραγωγή** — σήμερα η μηχανή τρέχει από PC· ο δρόμος `recompute|publish` θέλει
   `--allow-production` και ρητό ΟΚ (το FK trap λύθηκε). Χωρίς αυτό ο αυτοματισμός **υπολογίζει +
   ειδοποιεί**, δεν δημοσιεύει.
2. **Σταθερές έκδοσης** στο `scripts/build-frontend-umb-ranking.js` (EDITION, UPDATED_AT,
   LAST_EVENT): στην αυτόματη ροή πρέπει να βγαίνουν από τα δεδομένα, αλλιώς «last update»
   παλιάς έκδοσης με νέα νούμερα.
3. Η μηχανή/τα scripts να υπάρχουν στον server (το `cebRankingEngine.ts` είναι ήδη στο mirror).

## 5. Παγίδες / αποφάσεις που πρέπει να ληφθούν

- **Οι ποινές απουσίας (−8/−16) και το πλάτος της 10ης ζώνης (31 ή 32 θέσεις,
  `UMB_WC_ZONES_31`) βγαίνουν από την ΕΠΙΣΗΜΗ λίστα της UMB**, όχι από τα ματς μας. Άρα αμέσως
  μετά το τουρνουά η νέα στήλη είναι 100% δική μας εκτίμηση· η ταύτιση έρχεται με τη νέα έκδοση της
  UMB. Ο έλεγχος πρέπει να συγκρίνει **μόνο τις στήλες που υπάρχουν στην επίσημη λίστα** και να
  αναφέρει «νέα στήλη, χωρίς επίσημη επαλήθευση ακόμη» — αλλιώς μπλοκάρει κάθε φορά.
- **Μία φορά ανά έκδοση** αλλάζει η σύνθεση A–K (η 12η διοργάνωση αντικαθιστά την παλιότερη).
  Νέα έκδοση = νέο edition slug → **rebuild του frontend** (`dynamicParams = false` στην
  `[edition]/page.tsx`). Μπορεί να αυτοματοποιηθεί, αλλά είναι αλλαγή δεδομένων → θέλει ΟΚ.
- **Ανοιχτή απόφαση χρήστη:** (α) δημοσίευση **αμέσως** της δικής μας εκτίμησης + ειδοποίηση όταν
  διαφέρει από την UMB, ή (β) υπολογισμός + ειδοποίηση τώρα, **δημοσίευση μόνο σε 100% ταύτιση**.

## 6. Εκτίμηση

Το κούμπωμα στο publish flow είναι μικρό (ένα σημείο κλήσης + ουρά/debounce + δοκιμή σε τοπική
βάση). Το ουσιαστικό έργο είναι η **Φάση Β** (μηχανή + δρόμος δημοσίευσης στην παραγωγή), που είναι
ήδη σχεδιασμένη.
